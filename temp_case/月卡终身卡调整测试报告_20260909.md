## 二、关键验证结论

### 已实机验证的核心行为
1. **弹窗替换（处理1）生效**：终身卡宣传弹窗 `UIForeverCardOpenAlert` 触发逻辑已全部注销（`PrivilegeMgr.ts` L150-167 注释），各种触发路径下均不再弹出（TC-002/009）；月卡弹窗在解锁事件时正常主动弹出且仅一次（TC-001/005）。
2. **首购展示（处理2）正确**：未购时首购区块显示且文案/图标与配置一致（TC-012 免广告卡等 8 张无 first_desc 的卡全部隐藏首购组件、无布局空洞）；已购后首购组件隐藏（TC-013）。
3. **首购发放链路通**：GM 充值订单回调（老号4282）→ 卡激活（buy_time>0）→ `UIRewards` 弹窗一次性展示 每日→首购→购买 奖励，顺序与配置一致（TC-014）；首购奖励 20013×1 精确到账（TC-019）；重复购买不重复发首购、expire_time 正常叠加（TC-016）；首购判定基于 buy_times 字段（TC-E07）。
4. **回归项正常**：剩余时间与"再次购买可延长时间"文案（TC-022）、每日奖励跨天重置（TC-020/E06）、弱网断连打开详情页不崩溃（TC-E01）、离线闯关/体验卡弹窗条件（TC-007）。

### 发现的问题与风险
1. **TC-006（不通过，待产品确认）**：在子界面（UIMail）触发系统解锁时弹窗未强弹（符合预期前半），但**回到主界面后弹窗也未出现**——`OnlyMain` 判定 `isMainInTop=false` 抑制弹窗后没有补弹逻辑。"延迟到回主界面再弹"未实现，需产品确认交互预期。
2. **TC-E02（风险提示）**：`UIPrivCard.ts` L151-176 `onClickRecharge` **无防连点处理**（无 `interactable=false`），存在重复拉起支付/重复下单风险。实机连点 15 次未崩溃，但订单层拦截无法在预览环境验证，建议开发补充防连点。
3. **TC-013 注意项**：月卡已购后 `case 2` 分支硬编码保留购买按钮（续购入口，`RechargeBtb.active=true` / `ActivedLb.active=false`），不显示"已激活"。若用例预期是"按钮隐藏/显示已激活"则与实现不一致，需产品确认（续购设计 vs 展示疏漏）。

## 三、未跑完/待复测标注说明

### 待复测（脚本问题非缺陷）——TC-008/010/011/021
详情 UI 未打开的直接原因是**测试脚本解锁的系统 ID 错误**：客户端 `SysIdEnum.PRIVILEGE = 39`（`GameEnum.ts` L139），脚本误解锁了 87。unlock 后调用 `showPrivilegeCardView(3)` 无异常但 UI 未实例化（场景树仅池化节点 `PrivCard_:false`）。相关显隐/文案逻辑已静态核对一致。**修正 ID 后预期可通过，需复测 4 条。**

### 实机受限待复测——TC-004/015/018
GM `recharge_notifykey` 对新号 61234 返回 OK 但 `buy_time` 恒为 0（3 次重试+重登无效），无法构造"终身卡已购"前置状态；同链路对老号 4282 充月卡已验证成功（TC-014），判定为新号环境限制而非功能缺陷。相关服务端拦截逻辑已静态核对（重复购买 `ALREADY_HAD_PRIVILEGE_CARD`，`mod_privilege.lua` L341-343）。**建议用 4282 充值终身卡后复测 3 条。**

### 环境受限（静态核对通过）——TC-017/023、TC-E03/E04/E05
- TC-017：过期续购需实机等 30 天；`mod_privilege.lua` L356-360 续购分支不重复发首购，逻辑正确。
- TC-023：红点 `redPointMgr.isActive` 未在 QA 桥暴露；L260-270 红点逻辑静态核对正确（1093/1094）。
- TC-E03：GM 充值为即时回调，无法模拟回调丢失；服务端以订单回调为准，无刷首购漏洞入口。
- TC-E04：无灌满背包的 GM 命令；建议手工补测满背包转邮箱。
- TC-E05：无法运行时改配置为空数组；两端核对均安全（客户端空循环、服务端跳过空数组）。
- TC-E02：见上述风险项。
